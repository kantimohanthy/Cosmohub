# CosmoHub v0.1 Provenance Pipeline

This document describes the v0.1 architecture proving the capability to maintain an end-to-end provenance chain from real-world sources to queried results.

## Workflow Pipeline

### 1. SOURCE
The pipeline begins with identifying authoritative sources.
*   **Implementation:** `Source` data model representing publisher, publication date, URL, and a quality hierarchy (e.g., `PRIMARY_INSTITUTIONAL`).
*   **Example:** ESA's press release on Boost! contracts for Isar Aerospace and RFA.

### 2. DOCUMENT
The raw content of the source is retrieved.
*   **Implementation:** `Document` data model storing the raw text independently from extracted intelligence, mapped to a `source_id`.

### 3. CLAIM
Information is extracted as first-class `Claim` entities rather than immediately being treated as absolute truth (edges).
*   **Implementation:** `Claim` model containing subject, predicate, object, the specific `evidence` text snippet from the document, a `confidence` status (e.g., `SOURCE_BACKED`), and bitemporal fields (`observed_at`, `valid_from`, `valid_to`).
*   **Integrity:** Validation rules enforce that a `SOURCE_BACKED` claim *must* have an associated `source_id` and explicit `evidence`.

### 4. ENTITY
Claims reference entities (Nodes).
*   **Implementation:** `Entity` model strictly typed (e.g., `Organization`, `LaunchVehicle`, `FundingEvent`).
*   **Constraint:** The pipeline validation ensures no dangling references; every subject/object in a claim must exist in the entity registry.

### 5. RELATIONSHIP
The graph topology is implicitly formed by `Claim` nodes connecting two `Entity` nodes.
*   **Implementation:** Predicates are strictly validated against a whitelist (e.g., `MANUFACTURES`, `RECEIVED_FUNDING`).

### 6. PROVENANCE
Confidence and source tracking is preserved at query time.
*   **Implementation:** Conflict resolution and temporal tracking (e.g., marking a claim `status = SUPERSEDED` when a fact changes without deleting the historical truth). `SYNTHETIC` data is strictly isolated via confidence labels.

### 7. QUERY
The "Lens" extracts intelligence from the graph of claims.
*   **Implementation:** `QueryEngine` executes graph traversals that output answers alongside their underlying provenance (e.g., "Isar Aerospace builds Spectrum [Source: ESA URL, Evidence: 'ESA is supporting...']").

## Current Scope vs. Simulation
*   **Implemented:** The strict data schemas, the validation engine, the temporal/provenance data structures, and the query engine.
*   **Simulated (Manual):** The NLP/extraction step parsing raw document text into structured claims is currently simulated via hardcoded instantiation in `pipeline/ingestion.py`. In a production v0.2, this would be an LLM-assisted or regex-based extraction pipeline.
